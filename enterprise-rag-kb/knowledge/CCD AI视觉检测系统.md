# CCD AI视觉检测系统

## 1. 概述

CCD（Charge-Coupled Device，电荷耦合器件）AI 视觉检测系统是电池产线质量管控体系中的核心自动化检测手段，广泛应用于产线各个工位的来料检测、过程监控和成品检验环节。与人工目视检查相比，AI 视觉检测具有无疲劳、高一致性、高速度和可量化追溯的压倒性优势，是实现 CPK≥1.33 的质量目标的关键技术支撑。

产线视觉检测系统采用分布式架构：在各个检测工位部署高分辨率工业相机（CCD/CMOS）和定制化光源，进行本地图像采集和初步处理，然后通过工业以太网（GigE Vision 或 Camera Link 协议）将图像传输至集中部署的 AI 推理服务器。推理服务器搭载高性能 GPU（NVIDIA A10 或同等算力），运行基于深度卷积神经网络（CNN）的缺陷检测模型，在毫秒级时间内完成图像分类、目标检测和语义分割等多类视觉任务，并将检测结果实时反馈至工位 PLC 和 MES 系统。

产线共部署超过 32 个 AI 视觉检测点位，覆盖电芯六面外观、涂胶胶线质量、焊缝成形质量、Busbar 定位精度、密封胶条完整性、产品标识喷码等关键检测场景。系统设计目标为：缺陷检出率（召回率）≥99.5%，误判率 ≤0.5%，单帧图像推理时间 ≤50ms（含数据传输、AI 推理和结果反馈全链路）。误判率控制之所以如此关键，是因为高误判率将导致大量合格品被错误拦截，严重影响产线节拍和直通率。

## 2. 子系统与关键技术

### 2.1 图像采集子系统

图像采集硬件决定了 AI 检测的信息输入质量，是"垃圾进，垃圾出"原则的第一道关口。产线各检测点位根据检测对象特点配置了差异化的成像方案：

- **相机选型**：主要采用 12MP（4000×3000）和 25MP（5120×5120）分辨率的全局快门（Global Shutter）CMOS 工业相机。全局快门可消除卷帘快门（Rolling Shutter）在运动物体拍摄时的果冻效应（Jello Effect），对于产线移动状态下的在线检测至关重要。像素尺寸通常为 3.45μm，对应物方分辨率 15-30μm（根据不同的物距和镜头倍率），足以分辨亚毫米级的细微缺陷。
- **光源方案**：根据检测目标的光学特性选择不同的照明方案。条形 LED 光源用于焊缝和胶线的低角度掠射照明，突出表面三维形貌特征；环形无影 LED 光源用于电芯表面均光照明，抑制表面反光；背光光源用于检测电芯边缘轮廓和对齐度；多光谱光源（含紫外波段 365nm）用于检测荧光示踪的涂胶胶线覆盖完整性。
- **触发与同步**：相机由工位 PLC 或光电传感器触发拍摄，触发信号与传送带编码器同步，确保在工件到达预设位置时精准抓拍。多相机系统（如同一工位部署多个角度相机）需要通过硬件触发同步，确保所有相机在同一时刻曝光。

### 2.2 AI 推理子系统

AI 推理是视觉检测系统的"大脑"。产线采用预训练+迁移学习+在线优化的模型策略：

- **模型架构**：针对缺陷分类任务采用 ResNet-50 或 EfficientNet-B3 架构，针对目标定位任务采用 YOLOv8 或 Faster R-CNN 架构，针对像素级缺陷分割采用 U-Net 或 DeepLabV3+ 架构。不同架构的选择基于检测任务的具体特性：分类模型适用于胶线断胶、焊缝氧化等全局特征明显的缺陷；目标检测模型适用于焊点定位、极柱角度判定等位置敏感的任务；分割模型适用于涂胶面积覆盖率、焊缝几何尺寸等需要像素级精度的测量任务。
- **训练数据**：基础模型使用 COCO 和 ImageNet 等大规模公开数据集进行预训练，获得通用的图像特征提取能力。然后在产线收集的标注数据集上进行迁移学习和微调。每类检测场景的训练数据量不少于 5000 张标注图像，包含合格样本和各类缺陷样本。数据标注由经过培训的标注人员使用 LabelImg 或 CVAT 等工具完成，标注质量通过双人交叉验证机制（每张图由两人独立标注，不一致处仲裁处理）来保证。
- **推理部署**：模型通过 TensorRT 或 ONNX Runtime 进行推理优化和加速，部署于 GPU 推理服务器。利用批量推理（Batching）和异步流水线（Pipelining）技术，最大化 GPU 利用率和吞吐量。每个检测点位的端到端推理时间（图像传输 + 预处理 + 模型推理 + 后处理 + 结果回传）控制在 50ms 以内。

### 2.3 模型管理与持续优化

AI 视觉检测模型不是"一次性部署完就万事大吉"的静态系统，而是需要持续迭代优化的动态系统：

- **模型版本管理**：所有部署的 AI 模型维护版本号（如 v2.3.1），通过 MLflow 或 DVC 等 MLOps 工具追踪每个版本的训练数据、超参数、评估指标和部署状态。模型升级须经过离线验证（测试集的召回率和精确率均满足目标）后，通过灰度发布方式逐步覆盖产线检测点位。
- **误判样本回流**：当产线发生误判（假阳性：合格品被判为缺陷；假阴性：缺陷品未被检出，通过后续人工抽检发现），操作人员可在 HMI 界面上一键标记误判样本，该样本被自动回流至训练数据集。每积累 500 张新样本后触发模型重训练流程，持续提升模型的鲁棒性和准确率。
- **数据漂移监控**：来料电芯或 Busbar 的外观特征可能随供应商批次变化而发生缓慢漂移（表面颜色、纹理、光泽度的微变）。系统通过监控模型输出的置信度分布变化来检测数据漂移——如果某类样本的置信度分布出现明显偏移（如高分样本比例下降），则提示需要进行模型微调。

## 3. 参数说明

| 参数 | 说明 | 标准值 | 风险 |
|------|------|--------|------|
| 相机分辨率 | 图像传感器的像素数 | 12MP-25MP | 分辨率不足无法检出微小缺陷 |
| 物方分辨率 | 单个像素对应工件表面的物理尺寸 | 15-30μm | 分辨率不足时细微缺陷（<50μm）漏检 |
| 缺陷召回率 | 实际缺陷中被AI检出的比例 | ≥99.5% | 召回率不足时缺陷品流入下游 |
| 误判率 | 合格品被AI判为缺陷的比例 | ≤0.5% | 误判率过高导致合格品被拦截和返工 |
| 单帧推理时间 | 图像从触发到结果输出的全链路时间 | ≤50ms | 超过节拍要求会成为产线瓶颈 |
| 模型置信度阈值 | 判定缺陷的最小置信度 | 0.85-0.95 | 过低增加误判，过高降低召回率 |
| 光源亮度衰减 | 光源在额定寿命内的亮度下降 | ≤20% | 亮度不足导致图像对比度下降，误判增加 |
| 训练数据量 | 每个检测场景最少标注样本数 | ≥5000张 | 数据不足模型欠拟合，泛化能力差 |
| 模型更新周期 | 模型增量训练的触发样本量 | 每500张新样本 | 更新过慢跟不上数据漂移 |
| GPU 利用率 | 推理服务器GPU使用率 | 60-80% | 过高无冗余算力，过低资源浪费 |

## 4. 常见问题与对策

**Q1：AI 模型误判率突然上升，但参数和硬件未变更？**
A：首先排查是否为数据漂移所致——检查近期来料的外观特征是否有变化（如电芯表面颜色、光泽度、Busbar 镀层外观等）。在 HMI 上快速浏览一批近期的漏检/误判样本，定性判断是否为新类型外观变化导致模型不适用。如果确认是数据漂移，紧急对策是临时提高模型置信度阈值（降低误判但提升漏检风险），同时立即启动增量训练流程，收集新样本并在一周内完成模型更新。长期对策是建立定期的模型性能评估机制，在数据漂移严重前主动触发模型更新。

**Q2：特定工位的相机频繁输出"过曝"或"欠曝"报警？**
A：检查光源亮度是否衰减——LED 光源在使用 30000-50000 小时后亮度会逐步下降。使用光强计实测工作距离处的照度并与原始设定值对比。如果光源确实衰减，需要更换 LED 模块或调整 PWM 驱动电流（在允许范围内）。同时检查相机镜头是否被粉尘或焊接烟尘污染——清洁镜头保护滤镜（用镜头清洁液和无尘纸）。还需确认自动曝光（Auto Exposure）功能的工作状态——某些场景下，工件表面反射率的变化（如不同批次的铝壳表面氧化程度不同）会导致自动曝光算法无法锁定最佳曝光参数，需要手动锁定曝光参数或重新标定自动曝光的目标灰度值。

**Q3：GPU 推理服务器响应延迟突增，部分检测点位出现超时？**
A：GPU 服务器的延迟突增可能与同时运行的多个 AI 模型争夺 GPU 资源有关。首先检查 GPU 显存使用率是否接近上限——如果显存不足，部分模型可能被换出到系统内存（Thrashing），导致推理速度急剧下降。对策：优化模型精度（使用 FP16 半精度或 INT8 量化降低显存占用）、增加 GPU 数量或升级显存更大的 GPU。另外检查推理批次（Batch Size）设置——如果为了吞吐量而设置过大的 Batch Size，会导致单个样本的推理延迟增加。在产线应用中，延迟优先于吞吐量，Batch Size 通常设置为 1-4。

**Q4：产线停机重启后，AI 模型无法正常加载或推理错误？**
A：设计稳健的模型加载和验证流程：系统启动时自动执行模型完整性校验（通过 MD5 或 SHA256 哈希值比对模型文件），确保模型文件未损坏。然后使用内置测试图像集（包含 50-100 张标准图像及其已知正确结果）进行推理验证，所有测试图像结果正确才允许系统进入正常工作状态。如果模型加载失败，记录详细错误日志并通知运维人员——常见原因包括：GPU 驱动版本不兼容（系统更新后驱动变化）、模型文件在磁盘读写时损坏、显存因硬件故障不可用。建议在系统启动脚本中加入冗余逻辑：尝试加载模型的上一个已知良好版本（Rollback），保证产线尽快恢复运行。

## 5. 安全注意事项

- AI 视觉检测系统的误判可能导致不合格品流入下游或合格品被误拦截，影响产品质量和产线效率。因此，AI 检测结果建议与另一独立检测手段形成冗余验证——特别是在安全相关的检测项目（如焊缝完整性、绝缘片安装等），AI 检测仅作为辅助判定，最终放行决策须基于独立物理测量（如电阻测试、耐压测试）的综合结论。
- AI 模型训练数据包含专利产品和工艺信息，具有商业敏感性。训练数据的存储和传输须遵循公司信息安全策略——数据存储于公司内部服务器且加密，数据传输通过内部网络（不通过公网），模型文件的访问权限受控，离职员工的数据访问权限及时吊销。不得将包含产品细节的标注图像上传至公有云 AI 训练平台。
- GPU 服务器的散热和功耗管理必须到位。NVIDIA A10 单卡功耗约 150W，多 GPU 满负荷运行时的机柜级散热需求达到 1-2kW。服务器机房须有恒温恒湿控制、冗余空调和烟雾探测。GPU 过热不仅导致寿命缩短，还可能因 ECC（Error Correction Code）报错增加而影响模型推理结果的正确性。
- 视觉系统的高度集成性使其与产线的机械、电气和控制系统紧密耦合。对视觉系统进行任何软件更新或模型升级前，须在离线仿真环境中充分验证，并制定详细的回滚方案。升级操作须在计划停机时间窗口内进行，由设备、工艺和质量三方人员共同在场确认升级后首批产品的检测结果正常。

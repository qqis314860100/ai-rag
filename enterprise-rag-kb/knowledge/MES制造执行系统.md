# MES制造执行系统

## 1. 概述

MES（Manufacturing Execution System，制造执行系统）是电池产线数字化运营的核心信息平台，位于企业 ERP（Enterprise Resource Planning）系统与车间底层 PLC/SCADA 控制系统之间的执行层。MES 系统对产线全部工位实施全方位的数据采集、过程控制、质量追溯和生产调度，是实现产线透明化、数字化、智能化管理的技术中枢。

产线 MES 系统基于工业互联网平台架构设计，采用"边缘采集层 + 平台服务层 + 业务应用层"三层体系。边缘采集层通过 OPC UA、Modbus TCP、MQTT 等工业通讯协议与各工位 PLC、测试设备、机器人控制器等底层设备连接，实现毫秒级的生产数据采集和指令下发。平台服务层运行于工厂中央服务器集群（采用主备+负载均衡的高可用架构），提供数据存储、消息队列、业务逻辑处理和 API 接口等核心服务。业务应用层以 Web 和移动端形式向前端用户（操作工、工艺工程师、质量工程师、生产管理人员）提供人机交互界面。

MES 系统在产线承担的核心功能包括：生产工单管理与排产、产品全流程追溯（从电芯 ID 到 Pack ID）、工艺参数下发与版本控制、过程质量控制（SPC 实时监控）、设备状态采集与 OEE 计算、异常事件管理与 Andon 系统、物料管理与消耗追踪、质量文档电子化管理等。系统设计须满足 IATF 16949 和 ISO 27001 的合规要求，支持每年 15 万 Pack 的生产数据存储和处理能力。

## 2. 系统架构与核心功能

### 2.1 边缘数据采集

边缘数据采集层是 MES 系统与物理产线的接口桥梁。每个工位部署一台工业边缘网关（Industrial Edge Gateway），运行实时数据采集和协议转换软件，核心功能包括：

- **多协议适配**：同时支持 OPC UA（与西门子/倍福/罗克韦尔 PLC 通讯）、Modbus TCP（与 EOL 测试柜通讯）、TCP/IP Socket（与机器人控制器和视觉系统通讯）、MQTT（与 IoT 传感器通讯）等工业主流通讯协议，无需在设备端做定制化开发。
- **数据预处理**：在边缘侧完成数据清洗、格式标准化、时间戳对齐和初步聚合，减少上传至中心服务器的数据量和延迟。例如，将 PLC 的毫秒级原始采样数据处理为秒级统计值（均值、最大、最小、标准差）后再上传。
- **断网缓存**：当边缘网关与中央服务器之间的网络中断时，采集数据暂存于网关本地存储（SSD，至少支持 48 小时缓存容量），网络恢复后自动补传，确保数据不丢失。
- **指令下发通道**：接收 MES 下发的工艺参数、BOM 清单、生产工单等信息，转发至对应工位的 PLC 或 HMI 执行。下发操作须经过身份认证和操作审计，所有下发记录存档不可篡改。

### 2.2 全流程产品追溯

电池产品的全生命周期追溯是 MES 系统的核心价值之一。追溯粒度覆盖以下层级：

- **电芯级追溯**：每颗电芯在来料时即被分配唯一 ID（激光刻码或贴标二维码），记录其出生批次、化成分容数据、分选测试数据、在产线每个工位的绑定位号和加工参数。
- **模组级追溯**：模组成品拥有唯一 ID（模组标签二维码），通过绑定的电芯 ID 列表追溯每个组成电芯的全套信息。模组级追溯记录还包含堆叠工位参数、焊接参数、EOL 测试数据。
- **Pack 级追溯**：Pack 成品拥有唯一 ID（Pack 铭牌+合格证二维码），通过绑定的模组 ID 列表和 Pack 总装过程数据实现全链路追溯。

追溯查询支持正向和反向两个方向：
- **正向追溯**（Forward Traceability）：给定电芯/模组 ID，快速定位其最终进入了哪个 Pack，以及沿途的全部加工参数和测试数据。
- **反向追溯**（Backward Traceability）：给定 Pack VIN（Vehicle Identification Number），快速回溯其所有内部物料的来料批次、加工历史和质量判定记录。在售后发生质量问题时，可在几分钟内完成问题 Pack 的物料溯源和受影响范围锁定，决定是否需要批量召回。

### 2.3 过程质量 SPC 控制

SPC（Statistical Process Control，统计过程控制）模块对关键工位的 CTQ（Critical to Quality，质量关键特性）参数进行实时统计监控：

- 对涂胶重量、焊接熔深、螺栓力矩、绝缘电阻等连续型质量参数建立 X-bar R 图或 X-MR（Individuals and Moving Range）控制图
- 控制界限设定为：UCL（Upper Control Limit，上控制限）= 目标值 + 3σ，LCL（Lower Control Limit，下控制限）= 目标值 - 3σ
- 当一个数据点超出控制限、或连续 7 点出现在中心线同一侧（Western Electric 规则的"七点规则"）时，系统自动发出 Amber 或 Red 级别的质量警报
- 所有超出控制限的事件须由质量工程师在系统中填写原因分析和纠正措施，形成闭环

SPC 模块还提供工序能力分析功能：自动计算每个关键 CTQ 参数的 CPK 值，并按班组、日、周的维度生成趋势图。CPK 值 <1.33 的工序须纳入持续改善计划（CIP，Continuous Improvement Plan）。

### 2.4 设备管理与 OEE

MES 系统通过采集各工位 PLC 的运行状态信号（运行、待料、故障、换型、保养等），自动计算整线和各工位的 OEE（Overall Equipment Effectiveness）：

```
OEE = 可用性(Availability) × 性能(Performance) × 质量(Quality)
```

其中：
- 可用性 = (计划运行时间 - 非计划停机时间) / 计划运行时间
- 性能 = (实际产出数量 × 理论节拍) / 实际运行时间
- 质量 = 一次合格品数量 / 总产出数量

OEE 数据实时显示在生产管理看板（Dashboard）上，支持按工位、班组、日/周/月等维度钻取分析。设备故障停机事件通过 Andon 系统实时推送至维修团队，同时启动故障计时，维修完成后记录故障原因代码和维修时长，形成设备 MTTR（Mean Time to Repair，平均修复时间）和 MTBF（Mean Time Between Failures，平均故障间隔）的统计分析基础。

## 3. 参数说明

| 参数 | 说明 | 标准值 | 风险 |
|------|------|--------|------|
| 数据采集频率 | 关键参数的数据采样周期 | 100ms-1s | 频率过低漏掉瞬时异常，过高存储压力大 |
| 边缘缓存容量 | 网络中断时本地缓存支持时间 | ≥48小时 | 缓存不足时网络中断导致数据丢失 |
| 追溯查询响应时间 | 单条追溯查询的响应时间 | ≤3秒 | 响应过慢影响售后和质量的快速决策 |
| 系统可用性 | MES系统全年正常运行时间占比 | ≥99.9% | 低于此目标影响全产线生产 |
| 数据保留期限 | 生产数据强制保留年限 | ≥15年 | 不满足IATF 16949要求的法定追溯期 |
| SPC 控制限 | X-bar R图的标准差倍数 | ±3σ | 过窄导致过多误报警，过宽漏掉真实异常 |
| CPK 目标值 | 关键工序的过程能力指数 | ≥1.33 | CPK不达标工序需纳入改善计划 |
| Andon 响应时间 | 异常事件发生后维修到达时间 | ≤5分钟 | 响应不及时延长生产线停机 |
| 用户操作审计保留期 | 操作日志保留时间 | ≥3年 | 不足影响ISO 27001合规审计 |
| 灾难恢复 RTO | 灾难故障后系统恢复目标时间 | ≤4小时 | 超出RTO影响产线复产 |

## 4. 常见问题与对策

**Q1：MES 显示物料追溯链断裂——某颗电芯在分选工位有记录，但后续工位找不到它的绑定数据？**
A：追溯链断裂通常是因为数据采集环节出现了数据丢失或 ID 读取失败。排查步骤：首先在边缘网关端检查该时段的数据采集日志，确认 ID 读取操作是否执行以及读取结果（可能因扫码枪瞬断、二维码污损、或光照干扰导致读取失败）。如确实读取失败，检查工位是否有 ID 读取失败的人工补录流程——操作人员应被 HMI 引导完成手动输入或替换失败标签。如果数据丢失发生在边缘网关向中央服务器的传输环节，检查断网缓存的补传日志，确认数据是否在某个时间点因网络问题未被成功上传。

**Q2：SPC 控制图频繁出现误报警（假阳性），质量工程师疲于"狼来了"？**
A：误报警过多的根因通常是控制限设置不合理（过窄）。解决方案：收集至少 25 个子组（每个子组 4-5 个样本）的历史数据，基于实际过程变差重新计算控制限（而不是使用设计理论值）。确认数据的正态性——如果数据分布偏态严重（如涂胶量有天然的单边下限），可考虑对原始数据取对数转换后再建立控制图，或改用 X-MR 图（不要求子组）。最后，适当调整 Western Electric 规则的应用范围——对于工艺成熟、CPK>2.0 的稳定工序，可以仅监控超出 ±3σ 的极端异常，减少对连续趋势的自动报警。

**Q3：MES 服务器负载高导致页面响应缓慢，特别是在多用户同时查询时？**
A：首先区分是数据库查询瓶颈还是应用服务器资源不足。使用数据库慢查询日志找出最耗时的 SQL 查询——常见的性能杀手包括大时间范围的追溯查询（无时间索引导致全表扫描）和实时的 OEE 仪表盘查询（高频刷新带来的重复计算）。优化方案：为追溯查询创建复合索引（如工位+时间、Pack_ID+时间）；将 OEE 计算等聚合查询结果预先计算并缓存至专门的汇总表中（如每小时/每天定时任务生成），仪表盘查询直接读取预计算结果而非实时聚合。如果优化后仍不足，考虑增加只读副本数据库用于报表和查询负载的分流。

**Q4：网络中断恢复后，MES 数据补传出现大量重复记录？**
A：这是典型的边缘网关补传机制与中央服务器去重机制不协同的问题。解决：在数据上报时引入全局唯一的业务 ID（如"工位ID+时间戳+序列号"），服务器端使用数据库的唯一约束（UNIQUE INDEX）或写入前查询去重逻辑确保同一条数据不会被重复写入。另一个常见原因是边缘网关在超时无确认时重复发送同一条数据（At-Least-Once 语义），优化方案是在网关与服务器的通讯协议中增加"请求确认+幂等接收"机制，即服务器在成功处理数据后返回确认 ID，网关收到确认后不再重复发送。

## 5. 安全注意事项

- MES 系统存储着产线的核心工艺参数、质量数据和产品追溯信息，属于企业核心数据资产。系统须部署在独立隔离的工业控制网络中（与办公网络通过防火墙物理隔离），仅开放经过严格授权的 API 接口供外部系统（如 ERP）访问。数据库须启用透明数据加密（TDE）和传输层安全加密（TLS 1.3）。
- 用户权限管理须遵循最小权限原则（Principle of Least Privilege）：操作工仅可查看本工位 HMI 界面和生产数据录入权限，无权修改工艺参数；工艺工程师可修改本区域工艺参数但不可更改全局系统配置；系统管理员不可查看具体的产品追溯数据（职责分离，避免单点权限滥用）。所有关键操作（参数修改、工单变更、数据删除）须经过双人审批或电子签名确认。
- MES 系统需要执行定期的数据备份和灾备演练。备份策略建议为：每日增量备份+每周全量备份，备份数据异地存储（距离主厂房至少 5 公里）。每半年进行一次灾备恢复演练（模拟主服务器硬件故障），验证备份数据的完整性和恢复流程的有效性，RTO（恢复时间目标）≤4 小时，RPO（恢复点目标）≤1 小时。
- MES 系统中的产品追溯数据（特别是 Pack 与 VIN 的关联信息）涉及最终用户隐私和车辆安全。这些数据的访问须严格控制并记录详细审计日志——什么人、什么时间、出于什么原因、查看了哪个 VIN 的追溯数据，审计日志保存期不低于 10 年。

# RAG 产物模块边界

`rag/app/artifacts/` 放运行时会被 RAG 服务调用的产物契约和生成规划逻辑，包括 Diagram IR、图片产物契约、可视化规划、知识图谱轻量规划，以及知识卡 / FAQ 等可沉淀资产的候选判断。

这个目录的代码属于产品链路：`rag/app/api/`、`rag/app/core/` 或其他运行时模块可以直接导入它，并且需要保持请求处理期间可用。

`rag/evals/` 放评估集、回归样例、离线质量检查脚本和评测数据。评估代码可以调用 `rag/app/artifacts/` 来验证产物质量，但运行时产物逻辑不要反向依赖 `rag/evals/`。

新增代码时按下面的边界放置：

1. 会进入 API 响应、回答 metadata、图解生成或知识资产沉淀链路的契约和函数，放在 `rag/app/artifacts/`。
2. 只用于离线评测、质量对比、回归样例或人工验收报告的代码和数据，放在 `rag/evals/`。
3. 如果某段逻辑既被运行时使用又被评测使用，先放在 `rag/app/artifacts/`，评测侧只作为调用方。

# 企业级文档知识库智能工作台升级方案

## 1. 定位纠偏

本项目不是学习 App，也不是课程产品。核心定位是面向企业生产、工艺、质量、设备、SOP、技术文档和问题排查的智能文档知识库。

可以借鉴 Sitor 的交互构思，但不能照搬其“学习路线”心智。可借鉴的部分是：

- 右侧栏轻量化，只保留高价值导航和沉淀。
- AI 自动判断回答是否需要图解、流程图、表格或图片。
- 结构化产物直接嵌入回答，而不是藏在工具按钮里。
- 每轮回答能沉淀出摘要、证据、笔记和后续行动。

最终产品心智应是：

```text
企业知识问答
  + 可追溯证据
  + 文档原文预览
  + 流程/SOP/结构图解
  + 会话路线图
  + 知识笔记与评论
  + 企业知识沉淀
```

学习只是其中一个使用场景，例如新人培训、岗位学习、SOP 熟悉；不是产品主方向。

## 2. 当前问题

### 2.1 右侧栏过重

当前右侧栏承担了会话导航、证据、笔记、结构化输出、图谱入口等多种职责，信息密度高但主次不清。企业用户真正需要的是快速定位、证据追溯和知识沉淀，而不是一个塞满入口的工具栏。

### 2.2 图解能力是后置按钮，不是回答的一部分

目前图谱需要用户在回答后手动点击生成。更好的体验是：AI 在回答时自动判断是否需要结构化产物。如果回答包含流程、分支、架构、参数对比、异常处理、SOP 步骤，就应自动生成对应 artifact。

### 2.3 前端承担了不该承担的规则

前端不应该识别关键词、判断流程、决定节点分类、决定证据挂载、决定图结构。前端可以决定交互和展示，但业务语义和图结构应由 RAG/API 生成。

### 2.4 图表渲染方式不够产品化

手写 SVG 很快会遇到布局、缩放、导出、响应式、交互和视觉质量问题。图解类产物应使用成熟开源渲染器，例如 Excalidraw、React Flow、ECharts。

### 2.5 企业知识沉淀不足

当前回答、引用、笔记之间已有基础能力，但还没有形成企业知识工作流：

- 某轮回答解决了什么问题？
- 引用了哪些资料？
- 这轮问答能沉淀成什么结论？
- 相关资料有没有评论、备注、风险提示？
- 后续相似问题能否复用这轮结论？

## 3. 升级目标

### 3.1 产品目标

把聊天页升级为企业知识工作台：

- 主聊天区负责问答、证据、artifact 和操作。
- 右侧栏负责路线图和知识笔记。
- RAG/API 负责语义判断、结构化产物生成、证据追溯和持久化。
- 前端负责高质量展示、定位、交互和局部编辑。

### 3.2 用户目标

用户在企业场景中可以完成：

- 查询某个工艺、设备、质量、SOP、异常问题。
- 获取有引用证据的回答。
- 自动看到适合当前问题的流程图、架构图、参数表或图解。
- 点击右侧路线图快速回到某轮问答。
- 将有价值的回答、引用、评论沉淀为知识笔记。
- 刷新或切换会话后仍保留图解、笔记、引用和路线图。

### 3.3 技术目标

- artifact 可持久化，不依赖临时前端状态。
- artifact 可复用、可重新生成、可追溯来源。
- 前端不写死业务判断规则。
- 低置信度不自动生成图，避免无意义产物污染页面。
- 图解失败不影响主回答链路。

## 4. 目标信息架构

### 4.1 主聊天区

每条 assistant 回答建议由以下模块组成：

```text
回答正文
引用证据
自动生成的 artifacts
后续追问
回答操作区
```

artifact 示例：

- 流程图：异常处理、SOP 步骤、审批流、测试流程。
- 架构图：系统模块、设备链路、服务调用关系。
- 思维导图：知识点归类、原因分析、风险分类。
- 数据图表：指标趋势、数量对比、比例分布。
- 表格：参数对比、标准清单、检查项。
- 图片：设备示意、培训插图、场景示意。

### 4.2 右侧栏

右侧栏只保留两个 tab：

```text
路线图
知识笔记
```

这里统一使用“知识笔记”作为企业知识库主命名；在新人培训或岗位学习场景中，可以把同一能力显示为“学习笔记”。

#### 路线图

路线图展示当前会话的关键问答节点：

- 节点标题
- 一句话总结精髓
- 对应消息定位
- 是否有引用证据
- 是否有 artifact
- 当前节点状态

状态建议：

- 已处理：已有完整回答和证据。
- 当前：用户正在查看或最近一轮。
- 待跟进：AI 或用户标记需要补充资料、二次确认、线下验证。

#### 知识笔记

知识笔记展示从当前会话沉淀的内容：

- 回答笔记
- 引用笔记
- 资料评论
- 风险提示
- 人工补充说明
- 关联文档和 chunk

笔记可以关联：

- session
- assistant message
- source
- document
- chunk

## 5. 核心架构

### 5.1 分层职责

```text
web
  展示、交互、定位、弹窗、artifact 渲染、局部编辑

api
  权限、会话、消息、artifact 持久化、笔记、审计、RAG 编排

rag
  检索、重排、回答、证据、可视化规划、结构化 artifact 生成
```

### 5.2 回答生成链路

升级后的非流式链路：

```text
用户问题
  -> api 创建 user message
  -> api 调用 rag/chat
  -> rag 检索并生成 answer/sources/confidence/followups
  -> rag 运行 visual planner
  -> rag 生成 artifact plan
  -> api 保存 assistant message
  -> api 保存 artifacts / roadmap item
  -> web 渲染回答、证据、artifact、右侧路线图
```

升级后的流式链路：

```text
用户问题
  -> SSE meta
  -> SSE token
  -> SSE done(answer/sources/confidence)
  -> api 保存 assistant message
  -> api 异步生成 artifacts
  -> SSE artifact_pending
  -> SSE artifact_ready
  -> SSE roadmap_delta
```

关键原则：回答优先，artifact 后补。图解生成不能阻塞主回答。

## 6. 数据模型

### 6.1 ChatArtifact

新增 `chat_artifacts` 表。

```ts
type ChatArtifact = {
  id: string;
  session_id: string;
  message_id: string;
  type: "diagram" | "flowchart" | "mindmap" | "architecture" | "chart" | "table" | "image";
  renderer: "excalidraw" | "react-flow" | "echarts" | "markdown" | "image";
  title: string;
  summary: string;
  reason: string;
  status: "pending" | "ready" | "failed";
  confidence: number;
  payload_json: string;
  source_ids_json: string;
  metadata_json: string;
  created_at: string;
  updated_at: string;
};
```

`payload_json` 根据 renderer 不同而不同：

- `excalidraw`：Excalidraw scene elements/appState/files。
- `react-flow`：nodes/edges/viewport。
- `echarts`：ECharts option。
- `markdown`：表格或结构化 Markdown。
- `image`：url/prompt/model/size。

### 6.2 RoadmapItem

新增 `chat_roadmap_items` 表。

```ts
type RoadmapItem = {
  id: string;
  session_id: string;
  message_id: string;
  title: string;
  essence: string;
  status: "done" | "active" | "follow_up";
  order_index: number;
  artifact_ids_json: string;
  source_ids_json: string;
  metadata_json: string;
  created_at: string;
  updated_at: string;
};
```

路线图不是教学章节，而是当前会话的“知识处理路径”。

### 6.3 笔记沿用现有 chat_notes

当前已有 `chat_notes`，可以继续使用。需要补强的是列表聚合方式和 UI 呈现：

- session 笔记：当前会话总结。
- message 笔记：某轮回答结论。
- source 笔记：某条引用资料的评论、补充、风险提示。

## 7. Visual Planner

### 7.1 职责

Visual Planner 负责判断是否需要生成 artifact，以及生成什么类型。

输入：

```text
用户问题
回答正文
引用资料
会话历史摘要
命中的文档类型
confidence
```

输出：

```json
{
  "should_create": true,
  "type": "flowchart",
  "renderer": "excalidraw",
  "title": "EOL 测试异常处理流程",
  "summary": "把测试异常处理拆成检查、判断、恢复和记录四步。",
  "reason": "回答包含顺序步骤和条件判断。",
  "confidence": 0.86
}
```

### 7.2 触发条件

建议分为规则预判和 LLM 判断。

规则预判：

- 出现流程词：先、再、然后、如果、否则、判断、恢复、记录、上传。
- 出现架构词：模块、服务、接口、链路、调用、依赖、分层。
- 出现 SOP/工艺词：操作步骤、检查项、标准、参数、异常处理。
- 出现对比词：区别、对比、优缺点、范围、标准。
- 出现数据词：数量、比例、趋势、统计、Top、分布。

LLM 判断：

- 低置信度不生成。
- 无证据或回答过短不自动生成。
- 明确用户要求“画图、图解、流程图、架构图、表格”时提高优先级。

### 7.3 类型选择

| 场景 | artifact | renderer |
|---|---|---|
| SOP、异常处理、审批、操作步骤 | flowchart | excalidraw |
| 系统结构、模块关系、设备链路 | architecture | excalidraw |
| 知识点归纳、原因分类、风险分类 | mindmap | react-flow 或 excalidraw |
| 指标、趋势、比例、数量对比 | chart | echarts |
| 参数、标准、检查项 | table | markdown |
| 场景示意、设备培训图 | image | image |

## 8. 渲染器选择

### 8.1 Excalidraw

适合：

- 企业培训图解
- 流程图
- 架构图
- SOP 图解
- 手绘白板感说明图

优点：

- 接近截图中的图解质感。
- 可以通过 scene JSON 渲染。
- 支持只读视图、滚动到内容、导出。
- 适合解释复杂概念。

推荐作为第一阶段主渲染器。

### 8.2 React Flow

适合：

- 复杂节点关系
- 可交互流程图
- 节点可展开的知识图谱
- 后续需要拖拽编辑的场景

不建议作为第一阶段主视觉方案，因为它更像节点编辑器，不如 Excalidraw 有解释型图解感。

### 8.3 ECharts

适合：

- 统计图
- 趋势图
- 参数对比
- 质量指标分析
- 文档命中分布

### 8.4 图片生成

适合：

- 设备示意图
- 工位操作培训图
- 安全防护插图
- 抽象概念海报

企业文档知识库中，图片生成必须受控：

- 默认不自动生成真实图片。
- 只在用户明确要求或特定培训场景中使用。
- prompt 需要脱敏。
- 生成图片需要持久化和权限控制。

## 9. API 设计

### 9.1 消息返回

`GET /api/chat/sessions/:id` 返回：

```ts
{
  session: ChatSession;
  messages: ChatMessage[];
  roadmap: RoadmapItem[];
  notes: ChatNote[];
}
```

每条 assistant message 可携带：

```ts
{
  artifacts: ChatArtifact[];
  roadmap_item?: RoadmapItem;
}
```

### 9.2 Artifact 接口

```text
GET    /api/chat/messages/:id/artifacts
POST   /api/chat/messages/:id/artifacts/generate
POST   /api/chat/artifacts/:id/regenerate
DELETE /api/chat/artifacts/:id
```

删除 artifact 是软删除或仅从当前会话隐藏，避免破坏审计记录。

### 9.3 路线图接口

```text
GET   /api/chat/sessions/:id/roadmap
PATCH /api/chat/roadmap/:id
```

可修改字段：

- title
- essence
- status

### 9.4 笔记接口

沿用现有 notes 能力，补充列表聚合：

```text
GET /api/chat/sessions/:id/notes/overview
```

返回按 message/source 聚合后的笔记和引用资料。

### 10.2 主聊天区 artifact 卡片

artifact 不放右侧栏，而是放在对应回答中：

```text
回答正文

┌──────────────────────────┐
```

### 10.3 右侧路线图

右侧路线图用于定位和总结：

```text

```

点击节点定位到对应回答。

### 10.4 知识笔记

知识笔记不是简单文本列表，而是企业知识沉淀：

```text

  引用评论
  风险提示

```

每条笔记显示：

- 所属回答
- 关联文档
- 关联引用
- 评论内容
- 创建人和时间

## 11. RAG 设计

### 11.1 新增模块

建议新增：

```text
rag/app/artifacts/
├── planner.py
├── schemas.py
├── excalidraw_generator.py
├── chart_generator.py
├── table_generator.py
└── image_prompt.py
```

### 11.2 planner.py

负责：

- 判断是否生成 artifact。
- 判断 artifact 类型。
- 输出生成理由和置信度。

### 11.3 excalidraw_generator.py

负责：

- 把流程、架构、思维导图转换为 Excalidraw scene。
- 控制节点位置、颜色、连线、手绘风格。
- 返回可持久化 JSON。

### 11.4 table_generator.py

负责：

- 从回答和引用中提取参数、标准、检查项。
- 输出 Markdown table 或结构化 table JSON。

### 11.5 chart_generator.py

负责：

- 只有在有明确数值数据时生成。
- 输出 ECharts option。

## 12. 渐进式迭代路线

### 阶段 0：文档和契约

目标：确定企业知识工作台方向，避免继续偏学习产品。

任务：

- 新增本方案文档。
- PRD 增加下一阶段队列。
- 定义 `ChatArtifact` 和 `RoadmapItem` 类型草案。

验收：

- 文档说明产品定位、架构、数据模型和迭代顺序。
- 不改运行时代码。

### 阶段 1：右侧栏瘦身

目标：把右侧栏改成 `路线图 / 知识笔记`。

任务：

- 重命名并重组右侧栏组件。
- 移除结构化图谱入口和杂项卡片。
- 路线图先基于现有 messages 计算临时数据。
- 知识笔记接入已有 chat_notes。

验收：

- 右侧栏只显示两个 tab。
- 路线图节点可点击定位消息。
- 笔记能展示、创建、编辑、删除。

### 阶段 2：Artifact 数据契约

目标：把图解从临时按钮结果变成持久化回答产物。

任务：

- API 新增 `chat_artifacts` 表。
- 消息格式返回 artifacts。
- 当前 `/diagram` 生成结果写入 artifact。
- 刷新页面后 artifact 仍存在。

验收：

- 生成图解后刷新页面仍可看到。
- artifact 与 message/source 有关联。
- 删除消息时 artifact 级联处理。

### 阶段 3：Excalidraw 图解渲染

目标：替换手写 SVG，提升视觉质量。

任务：

- 安装 `@excalidraw/excalidraw`。
- 新增 `ExcalidrawArtifact`。
- RAG 输出 Excalidraw scene。
- 原 Diagram IR 可作为兼容输入转换成 scene。

验收：

- 流程图/架构图呈现白板手绘风。
- 支持放大弹窗、滚动查看、导出。
- 前端不写关键词和图结构规则。

### 阶段 4：Visual Planner 自动生成

目标：让 AI 自动判断是否需要图解或表格。

任务：

- RAG 新增 planner。
- API 在回答完成后触发 artifact 生成。
- 流式回答先完成，artifact 后补。
- 低置信度不自动生成。

验收：

- 问 SOP/流程/异常处理时自动出现流程图。
- 问参数/标准时自动出现表格。
- 普通闲聊或无证据回答不生成 artifact。

### 阶段 5：知识笔记增强

目标：让回答、引用、评论形成企业知识沉淀。

任务：

- 笔记列表按回答和引用聚合。
- 引用详情中显示相关评论。
- 支持从 artifact 或回答生成笔记草稿。

验收：

- 用户能从一轮问答沉淀结论。
- 用户能对某条引用资料追加评论。
- 后续打开会话能看到完整沉淀。

### 阶段 6：图片生成能力

目标：补充真正文生图，但作为受控能力。

任务：

- 后端定义 image artifact。
- 接入图片生成模型。
- 加 prompt 脱敏和权限控制。
- 图片生成异步化。

验收：

- 用户明确要求时可生成图片。
- 图片 artifact 可持久化、可查看、可删除。
- 不把受限文档原文直接暴露给图片模型。

## 13. 风险和边界

### 13.1 不要把前端变成规则引擎

前端只消费后端返回的 artifact。以下逻辑不能放前端：

- 关键词提取
- 图类型判断
- 节点分类
- 证据挂载
- 参数/风险识别
- 是否自动生成

### 13.2 不要自动生成过多图

artifact 过多会降低企业知识库的专业感。必须有阈值：

- 低置信度不生成。
- 无证据不生成，除非用户明确要求。
- 回答过短不生成。
- 同一轮最多自动生成 1 个主 artifact。

### 13.3 不要牺牲回答速度

artifact 生成必须可异步。用户先看到回答，再看到图解补充。

### 13.4 图片生成必须受控

企业文档可能包含内部信息。图片 prompt 要脱敏，权限要和原会话/文档一致。

## 14. 完成标准

整体升级完成后，应满足：

- 右侧栏只有 `路线图 / 知识笔记` 两个主 tab。
- 路线图节点可定位到对应回答。
- 每个路线图节点有一句总结精髓。
- 回答可以携带持久化 artifacts。
- artifact 可自动生成，也可手动重新生成。
- 图解使用 Excalidraw 或同级开源渲染器，不再依赖手写 SVG。
- 前端不写业务图规则。
- 引用资料、评论、笔记能关联到回答和 source。
- 刷新页面后回答、证据、artifact、路线图、笔记都可恢复。
- 图解失败不影响主回答。
- 图片生成作为受控增强能力，而不是默认能力。

## 15. 第一轮建议任务

第一轮不要直接做图片生成，也不要先做复杂自动 planner。建议先做：

```text
右侧栏瘦身为 路线图 / 知识笔记
```

原因：

- 用户已经明确指出右侧栏太重。
- 这是最直接的视觉和信息架构改善。
- 可以先基于现有 messages 和 chat_notes 做，不需要新表。
- 风险低，能快速确认产品方向。

第二轮再做：

```text
chat_artifacts 持久化契约
```

第三轮再做：

```text
Excalidraw artifact 渲染
```

第四轮再做：

```text
Visual Planner 自动生成
```

# 聊天体验重构计划

> 目标：把聊天区升级为“问答 + 引用详情 + 会话导航 + 结构化输出”的完整体验。

## 0. 依赖关系

```
需求定义
  -> 数据契约
  -> 前端骨架
  -> 后端接口
  -> RAG 元数据增强
  -> 统一预览器 / 图谱能力
  -> 联调验证
```

## 1. 阶段一：交互语义定稿

### 目标

先把卡片、按钮、右侧栏、引用的角色边界固定下来。

### 要做什么

- 定义用户消息和助手消息的可操作项。
- 定义删除的确认语义。
- 定义发送中按钮从“发送”切换到“中断”。
- 定义引用点击后的入口和容器。

### 参与方

- 前端：消息卡片、输入框、引用入口
- 后端：删除语义、反馈语义的接口确认
- RAG：引用数据颗粒度确认

### 验证

- 聊天发送
- 中断生成
- 删除确认
- 点赞/点踩切换

## 2. 阶段二：右侧栏改造

### 目标

把右侧从“全量引用列表”改成“会话导航器”。

### 要做什么

- 章节树
- 当前会话脉络
- 学习笔记
- 最近证据
- 收藏证据

### 依赖

- 需要引用详情数据
- 需要章节/段落元数据

### 验证

- 切会话后右侧内容正确刷新
- 章节点击可快速定位
- 笔记可增删改查

## 3. 阶段三：引用详情弹窗/抽屉

### 目标

把“引用”从侧栏里拆出来，变成按需打开的详情视图。

### 要做什么

- 引用详情弹窗 UI
- 原文/上下文/跳转/收藏/加入笔记
- 关联当前回答中的引用编号

### 依赖

- RAG 要返回更完整的 chunk/context 结构
- 后端要能取引用详情和原文片段

### 验证

- 点击引用编号可打开详情
- 可查看前后文
- 可加入笔记

## 4. 阶段四：统一文件预览器

### 目标

把 `md/pdf/html/code/raw` 合成一个统一预览壳。

### 要做什么

- Markdown 渲染
- PDF 预览
- HTML 清洗和隔离
- 代码高亮
- 原文模式切换

### 依赖

- `PDF.js` 或同级方案
- Markdown 解析和代码高亮依赖
- HTML 安全清洗策略

### 验证

- 同一预览壳切换不同文件类型
- PDF 页码定位正常
- HTML 无脚本污染

## 5. 阶段五：结构化图谱

### 目标

让对话内容能被 AI 整理成思维导图、流程图、时序图。

### 要做什么

- 设计图谱生成入口
- 支持从会话 / 回答 / 引用生成
- 支持导出 PNG/SVG/Markdown

### 依赖

- RAG 或后端需要提供结构化节点输出
- 前端需要图谱渲染层

### 验证

- 从会话生成图谱
- 从引用生成图谱
- 图谱可导出

## 6. 阶段六：联调和回归

### 目标

确保新交互不会破坏现有聊天主流程。

### 要做什么

- 浏览器回归
- 长会话回归
- 切换会话回归
- 删除/收藏/反馈回归

### 验证清单

- 发送消息
- 中断流式生成
- 切换会话
- 点击引用
- 打开预览
- 添加笔记
- 生成图谱

## 7. 推荐执行顺序

1. 先定交互语义。
2. 再改前端骨架。
3. 再补后端接口。
4. 再补 RAG 元数据。
5. 再做统一预览和图谱。
6. 最后联调回归。

## 8. 切分建议

- `web`：消息卡片、右侧栏、引用详情、预览器、图谱 UI。
- `api`：消息/引用/笔记/删除/图谱接口。
- `rag`：检索元数据、上下文窗口、图谱结构输入。

# 运行时拓扑与数据流

这份图是 [项目架构总览](../项目架构总览.md) 的可视化补充，描述当前 `web` / `api` / `rag` 三服务运行时边界、主要存储和核心链路。

## 运行时拓扑

```mermaid
flowchart LR
  user["用户 / 浏览器"]
  web["web\nVite :5174\nReact + TypeScript"]
  api["api\nExpress :3001\n认证 / 会话 / 文档 / artifact / 审计"]
  rag["rag\nFastAPI :8000\n解析 / 检索 / AnswerIR / DiagramIR"]
  sqlite[("SQLite\ndata/ai-rag.db")]
  uploads[("上传文件\ndata/uploads/")]
  chroma[("ChromaDB\ndata/chroma/")]
  knowledge[("种子知识\nknowledge/")]
  llm["LLM / Embedding Provider"]

  user -->|"页面操作"| web
  web -->|"HTTP + SSE\n/api/*"| api
  api -->|"读写业务状态"| sqlite
  api -->|"保存 / 读取上传文件"| uploads
  api -->|"HTTP\n/rag/*"| rag
  rag -->|"读取待索引文件"| uploads
  rag -->|"读取种子文档"| knowledge
  rag -->|"向量写入 / 检索"| chroma
  rag -->|"embedding / chat completion"| llm
```

## 问答与结构化产物流

```mermaid
sequenceDiagram
  autonumber
  participant U as 用户
  participant W as web
  participant A as api
  participant R as rag
  participant DB as SQLite
  participant VS as ChromaDB
  participant L as LLM

  U->>W: 输入问题
  W->>A: POST /api/chat
  A->>DB: 创建用户消息 / 读取会话历史
  A->>R: POST /rag/chat
  R->>VS: 检索相关 chunk
  R->>L: 生成 AnswerIR + answer + visual_plan
  R-->>A: 返回 answer / sources / AnswerIR / visual_plan
  A->>A: zod 校验 RAG 契约
  A->>DB: 保存 assistant 消息和引用 metadata
  A-->>W: 返回回答、引用和可视化计划
  W-->>U: 展示带证据回答

  opt 生成图解产物
    W->>A: POST /api/chat/messages/:id/artifacts/generate
    A->>R: POST /rag/diagram/generate
    R->>L: 生成 DiagramIR
    R-->>A: 返回 DiagramIR
    A->>A: 校验质量门槛和拓扑
    A->>DB: 保存 chat_artifacts
    A-->>W: 返回 artifact + payload
    W-->>U: 弹窗渲染 Excalidraw 图解
  end
```

## 文档导入与检索流

```mermaid
flowchart TB
  upload["上传文档\nweb -> api"]
  persist["api 保存文件\n写 documents 记录"]
  ingest["api 请求 rag ingest"]
  parse["rag 解析 / 清洗"]
  chunk["分块 + 元数据归一"]
  embed["embedding"]
  index["写入 ChromaDB"]
  query["用户提问"]
  retrieve["rag 检索 chunk"]
  answer["生成带引用回答"]

  upload --> persist --> ingest --> parse --> chunk --> embed --> index
  query --> retrieve --> answer
  index --> retrieve
```

## 边界原则

- `web` 只访问 `api`，不直连 `rag`、SQLite 或 ChromaDB。
- `api` 负责用户身份、会话、权限、持久化、审计和契约校验。
- `rag` 负责解析、检索、模型调用和结构化 IR 生成，不保存用户会话状态。
- `AnswerIR` / `DiagramIR` 的破坏性契约问题必须停在 `api/src/services/ragClient.ts` 边界。

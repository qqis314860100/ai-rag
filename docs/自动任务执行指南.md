# Codex 自动任务执行指南

## 目标

让 Codex 可以按本地任务清单自动执行项目任务，而不是只能在当前聊天里手动推进。

## 工作方式

任务队列默认放在：

```text
.codex/task-queue/
├── pending/   待执行任务
├── running/   正在执行
├── done/      已完成
├── failed/    执行失败
└── logs/      执行日志
```

`.codex/` 已被 `.gitignore` 忽略，所以任务队列是本地运行状态，不会污染仓库提交。

## 添加任务

```bash
scripts/codex_task_add.sh "修复聊天滚动问题" "检查聊天页面发送消息后是否自动滚动到底部，修复并验证后提交。"
```

也可以直接在 `.codex/task-queue/pending/` 下新建 `.md` 文件。

## 手动执行

```bash
scripts/codex_task_runner.sh
```

默认一次只执行一个任务。要一次执行多个：

```bash
CODEX_TASK_MAX_TASKS=3 scripts/codex_task_runner.sh
```

默认要求工作区干净，避免自动任务误伤当前人工改动。如果确实要允许脏工作区：

```bash
CODEX_TASK_ALLOW_DIRTY=1 scripts/codex_task_runner.sh
```

## 安装后台自动执行

macOS 使用 `launchctl`：

```bash
scripts/安装codex自动任务.sh 1800
```

上面的 `1800` 表示每 30 分钟检查一次任务队列。

卸载：

```bash
scripts/卸载codex自动任务.sh
```

## 安全边界

- 自动任务会调用 `codex exec`。
- 自动任务 prompt 会要求 Codex 读取项目规则、验证后提交、不要混合服务提交。
- 自动任务默认拒绝在脏工作区运行。
- 如果任务无法安全完成，应该进入 `failed/` 并保留日志。

## 建议任务格式

```markdown
# 任务标题

## 背景

为什么要做这个任务。

## 任务

具体要修改或验证什么。

## 验收

- 需要跑哪些命令
- 需要验证哪些页面或接口
- 是否需要提交
```

# 企业级 UI 协作工作流

## 1. 目的

本项目的 UI 工作流目标不是“让 AI 做得好看点”，而是把 AI 当作可管理的设计协作团队：

```text
定方向 -> 起稿 -> 审查 -> 打磨 -> 优化 -> 适配 -> 截图验收
```

这套流程只在 UI 任务需要时启用，不替代 [项目执行规则清单](EXECUTION_RULES.md)。

## 2. 适用范围

| 类型 | 是否完整使用 Impeccable 流程 | 验证 |
|------|-------------------------------|------|
| 文案、间距、按钮状态 | 否 | 最小检查或人工检查 |
| 普通组件、卡片、弹窗、右侧栏 | 部分使用 critique / polish | `pnpm run build:web` + 定点检查 |
| 聊天主界面、Artifact、图解弹窗、知识资产页 | 是 | 构建 + 截图 + 必要浏览器 smoke |
| 发布前 UI 体验检查 | 是 | 多断点截图 + 关键路径 smoke |

## 3. 项目内安装

Impeccable 已安装在项目内：

```text
.agents/skills/impeccable
```

配套上下文：

- [PRODUCT.md](../PRODUCT.md)：产品定位、用户、场景和反参考。
- [DESIGN.md](../DESIGN.md)：视觉方向、组件规则和验收标准。

新开 Codex / Claude 会话后，项目内 skill 才会被完整识别。

## 4. 推荐流程

### 4.1 起稿

用于新页面、大组件或显著 UI 改造：

```text
$impeccable craft <目标组件或页面>
```

起稿前必须明确：

- 页面服务哪个用户和任务。
- 当前是企业工具、图解、文档预览还是知识资产场景。
- 哪些信息最重要，哪些操作必须贴近上下文。

### 4.2 审查

用于高影响 UI、图解、发布前体验检查：

```text
$impeccable critique <页面、组件或截图问题>
```

审查重点：

- 信息层级是否清楚。
- 操作是否靠近上下文。
- 是否有 AI Slop 痕迹。
- 对比度、焦点态、空态、错误态是否可靠。
- 图解是否语义正确、布局可读。

### 4.3 打磨

用于统一间距、字号、颜色、状态、文案和组件一致性：

```text
$impeccable polish <目标>
```

每轮只处理 1 到 3 个最高影响问题，避免一次改太多导致无法判断效果。

### 4.4 优化

用于大型弹窗、Excalidraw、Markdown、知识资产列表等可能影响性能的 UI：

```text
$impeccable optimize <目标>
```

优化重点：

- 是否需要懒加载。
- 是否存在不必要重渲染。
- 动效是否影响输入、滚动或流式稳定。
- 图解和文档预览是否阻塞主回答。

### 4.5 适配

用于移动端、普通笔记本和宽屏：

```text
$impeccable adapt <目标>
```

适配重点：

- 聊天输入框不跳。
- 消息列表不被右侧栏或弹窗挤压。
- 图解弹窗可滚动，文字不溢出。
- 右侧栏在移动端退化为可控抽屉或隐藏入口。

## 5. 验收标准

- 不出现明显 AI Slop：无星星装饰、霓虹渐变、无意义卡片套卡片。
- 文本不溢出，按钮和图解节点尺寸稳定。
- 关键路径不闪跳，尤其是发送、流式、重试、弹窗打开。
- 图解必须先语义正确，再追求视觉质感。
- 高影响 UI 必须看实际截图，不能只看代码和构建结果。

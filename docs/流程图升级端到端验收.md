# 流程图升级端到端验收

## 验收范围

本次验收覆盖流程图从 RAG 语义生成、API artifact 契约与持久化、到 Web 图解渲染的主链路。

验收目标不是证明所有业务流程都完美，而是确认以下高风险能力已经有可复查证据：

1. 低信息或拒答内容不生成假流程图。
2. 分支判断保留业务标签。
3. loop / fallback 连线方向和语义可区分。
4. 多角色流程可通过 lane metadata 进入泳道图渲染。
5. artifact 通过 API 持久化，刷新后可随消息恢复。
6. 前端只消费结构化 DiagramIR，不在页面里抽取业务规则。
7. 图解弹窗在桌面页面可正常打开主界面，构建和类型检查通过。

## 已知边界

- 当前验收覆盖的是最小闭环，不等价于所有业务文档都能生成高质量流程图。
- 自动化浏览器未覆盖真实点击生成 artifact 的完整远端 LLM 链路；该链路依赖当前 API key 和 RAG 服务运行状态。
- `rag/tests/test_quality_eval_suite.py` 中图片产物合同用例属于图片生成安全链路，不纳入本次流程图验收范围。
- 后续如果要做发布级验收，应增加一条固定测试文档和固定测试账号，跑真实“提问 -> 自动/手动生成 artifact -> 刷新恢复 -> 打开弹窗”的 Playwright 流程。

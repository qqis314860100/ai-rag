## 目标

把仓库变成一个长期可协作、可验证、可回滚的项目，而不是只靠聊天记忆维持一致性。

## 服务边界

### `web`

- 只负责页面、交互、路由、视觉状态和客户端缓存
- 通过 HTTP 调用 `api`
- 不直接访问数据库，不直连 `rag`

### `api`

- 负责认证、会话、文档、反馈、收藏、统计和审计
- 负责把前端请求转换成稳定的后端接口
- 通过服务客户端调用 `rag`
- 不放前端 UI 逻辑

### `rag`

- 负责文档解析、切分、向量化、检索、提示词组装和模型调用
- 不承载前端路由
- 不承载用户界面逻辑

## 文档标准

- 对话过程中沉淀出来的需求、设计、架构、技术说明、计划、复盘等文档，新增时使用中文文件名和中文标题
- 不强制重命名历史英文文档
- 不影响代码、配置、脚本、测试、资源文件和标识符命名

## 变更规则

- 单个 commit 只允许覆盖一个服务
- 需要跨服务时，先拆分成多个 commit
- 按风险等级完成验证后再提交；小改动不强制真实流程回归
- 新规则优先写进文档，再变成脚本、lint 或 CI 检查

## 推荐验证

- A 级小改动：目标函数、语法、类型或局部 smoke
- B 级普通服务改动：相关服务 build/test 和定点 smoke
- C 级核心链路：真实浏览器/API/RAG 链路验证
- 全量 `pnpm run verify`、`pnpm run audit:harness` 和 `api/tests/run-tests.sh` 只在高风险或阶段验收时运行

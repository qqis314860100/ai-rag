# 工程结构

读取 Agent 入口、构建文件和相关架构章节，输出当前模块边界、依赖方向、允许的跨层入口、
所有权和任务涉及的最小文件范围。不得凭通用分层模板覆盖项目事实。



## 本项目事实（ai-rag，2026-08 合并远端后）

- 三个服务，边界严格：`web/`（React 19 + Vite + Tailwind，端口 5174，
  页面在 `src/pages/`，聊天在 `src/features/chat/`）、
  `api/`（Express + better-sqlite3，端口 3001，JWT 认证/RBAC/审计/限流，
  路由拆分在 `src/routes/chat/`、RAG 客户端在 `src/services/rag/`）、
  `rag/`（FastAPI + ChromaDB，端口 8000，pipeline 拆包在 `core/pipeline/`）
- 依赖方向：web → api → rag（HTTP + `X-API-Key`）；rag 不感知用户、不读业务库
- 入口：AGENTS.md（通用入口）+ CLAUDE.md（Claude 入口）+ README.md
- 提交规则：commit 保持单主题；同一主题允许跨服务，不能混无关改动；
  Conventional Commits，描述写中文，正文用编号列修改点
- 权威文档：docs/EXECUTION_RULES.md（执行细则唯一来源）、docs/架构标准.md、
  docs/PRD.md（需求）、docs/decisions/（决策）；新建讨论型文档用中文文件名
- 常用命令：`pnpm dev`（web+api）/ `pnpm dev:rag` / `pnpm run verify` /
  `pnpm run test:api` / `pnpm run audit:harness` / `pnpm run audit:diff -- --strict`
- 数据边界：`data/`（SQLite + 上传 + Chroma，gitignore）；生产环境必须配置
  `JWT_SECRET` 与 `RAG_API_KEY`

检查重点：

- 新依赖是否沿允许方向流动。
- 公开契约、数据和安全边界是否被识别。
- 变更是否放在现有职责边界内。
- Sensor 是否能检测越层、漏测或构建问题。

Gate：工程结构结论有仓库证据，且计划没有未解释的跨层依赖。

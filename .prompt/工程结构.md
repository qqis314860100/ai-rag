# 工程结构

读取 Agent 入口、构建文件和相关架构章节，输出当前模块边界、依赖方向、允许的跨层入口、
所有权和任务涉及的最小文件范围。不得凭通用分层模板覆盖项目事实。



## 本项目事实（ai-rag）

- 三个服务，边界严格：`web/`（React 19 + Vite + Tailwind，端口 5174）、
  `api/`（Express + better-sqlite3，端口 3001，JWT 认证/RBAC/审计/限流）、
  `rag/`（FastAPI + ChromaDB，端口 8001，解析→分块→Embedding→检索→LLM）
- 依赖方向：web → api → rag（HTTP + `X-API-Key`）；rag 不感知用户、不读业务库
- 提交规则：一个 commit 只改一个服务（`api`/`web`/`rag`），Conventional Commits，
  `scope` 限 `api|web|rag`；`docs`/`chore` 用于仓库级变更
- 权威文档：CLAUDE.md（入口）、docs/ARCHITECTURE.md（边界）、docs/PRD.md（需求）、
  docs/decisions/（决策）、docs/FINDINGS.md（已知问题）
- 常用命令：`pnpm dev` / `pnpm dev:rag` / `bash scripts/check-harness.sh` /
  `bash api/tests/run-tests.sh` / `bash api/tests/security/security-tests.sh`
- 数据边界：`data/`（SQLite + 上传 + Chroma，gitignore）；生产环境必须配置
  `JWT_SECRET` 与 `RAG_API_KEY`

检查重点：

- 新依赖是否沿允许方向流动。
- 公开契约、数据和安全边界是否被识别。
- 变更是否放在现有职责边界内。
- Sensor 是否能检测越层、漏测或构建问题。

Gate：工程结构结论有仓库证据，且计划没有未解释的跨层依赖。
